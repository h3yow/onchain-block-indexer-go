# onchain-block-indexer-go

本地可回滚的链上区块与交易索引流水线。使用本地生成的模拟链（`SimChain`）作为数据源，
保证正常推进、重复摄入与链重组之后的索引结论一致且可解释。

## 结构

```
internal/indexer/
  types.go         区块/交易类型与可区分的错误分类（ErrorKind）
  store.go         索引存储：校验、幂等写入、回滚、检查点持久化、一致性快照
  source.go        数据源抽象与本地模拟链（分叉与故障注入）
  pipeline.go      摄入流水线：并发拉取、按序提交、重组回滚、指标
  inspect.go       巡检对账：逐高度只读核对，问题按类别分开列出
  heal.go          巡检自愈：回滚到共同祖先后顺序重建，受重组深度上限约束
  audit_trail.go   重组旁路留痕：被放弃分支的持久化记录、反查与容量清理
  pipeline_test.go 覆盖正常/重复/重组/并发/故障/恢复的测试
  heal_test.go     覆盖巡检分类/自愈等价全量重放/幂等/超限拒绝/留痕/并发的测试
```

## 数据源约定

- `Source` 接口：`FetchBlock(height)` 按高度拉取区块，`Tip()` 返回链尖高度。
- 高度从 1 开始连续编号；每个区块必须携带 `Height / Hash / ParentHash`，
  交易必须携带 `Hash / From / To`。字段缺失或区块内交易哈希重复属于
  **非法数据**，不会被静默丢弃，而是以 `KindInvalidData` 失败返回。
- `SimChain` 由 seed 确定性生成：同一 seed 同一高度内容恒定；
  `Fork(h)` 后高度 h 起切换为新分支（哈希不同、父哈希衔接）；
  `InjectTransient(n)` / `InjectFatalAt(h)` 注入临时/不可恢复失败。

## 重组与回滚规则

- 提交前比对：同高度同哈希 → 幂等跳过（计 `Duplicates`）；
  同高度不同哈希或父哈希与链尖不符 → 进入重组处理。
- 重组时从冲突高度向下寻找索引与数据源一致的**共同祖先**，
  回滚深度 = 当前链尖 − 共同祖先高度。
- 深度 ≤ `MaxReorgDepth`：`RollbackTo(祖先)` 删除其上的全部区块与交易
  （被抛弃分支无任何残留），随后同步重建受影响区间并继续按序提交。
- 深度 > `MaxReorgDepth`：返回 `KindReorgTooDeep` 明确拒绝，
  索引保持原状，绝不静默继续。

## 错误分类

| 分类 | 含义 | 处理 |
|---|---|---|
| `invalid-data` | 区块/交易字段缺失或非法 | 不计入索引，立即失败并计数 `InvalidBlocks` |
| `transient-source` | 数据源临时失败 | 自动重试（`MaxRetries` 次），计数 `TransientErrs` |
| `fatal-source` | 数据源不可恢复失败 | 不重试，终止本次同步，计数 `FatalErrs` |
| `reorg-too-deep` | 重组深度超限 | 拒绝并保持索引原状 |
| `internal` | 索引器内部错误（如检查点写失败、高度不连续） | 终止并返回 |

所有错误为 `*indexer.Error`，携带高度、区块哈希与原因，可用 `KindOf(err)` 判定类别。

## 巡检对账（`Inspect`）

随时可手动触发的只读对账：`ix.Inspect(ctx)` 返回 `InspectionReport`，
**索引干净时不改动任何持久化状态**（不写检查点、不动指标、不写留痕）。
巡检在开始时取索引的一致性快照，与摄入/重组/自愈相撞时只会看到完整的
“回滚前”或“重建后”状态，不会读到写到一半的中间状态。

对账区间为 `[1, min(索引链尖, 数据源链尖)]`，逐高度拉取数据源并与快照比对；
问题按类别分开（各类可用 `report.Missing()` 等访问器单独取出），不混成一个失败：

| 类别（`IssueKind`） | 判定口径 |
|---|---|
| `missing` 缺高 | 已覆盖区间内索引缺失某个连续高度（高度缺口） |
| `mismatch` 内容不符 | 同一高度索引区块与数据源区块哈希或字段（含逐笔交易）对不上 |
| `parent-broken` 父链断裂 | 两个相邻且都存在的高度之间，子块 `parentHash` ≠ 父块哈希 |
| `extra-block` 多余区块 | 高度只存在于索引（超出数据源链尖 / 数据源已无此高度） |
| `orphan-tx` 游离交易 | 交易表记录不被任何已索引区块引用，或指向高度/区块与所在区块不符 |

每条 `Issue` 带高度、索引侧/数据源侧区块标识与可解释的判定依据。
数据源**临时失败**在巡检内自动退避重试但不影响摄入计数；**不可恢复失败**直接返回。
摄入尚未到达的高度（索引链尖 < 数据源链尖的部分）不算问题，避免把正常写入误判成脏数据。

## 就地自愈（`Heal`）

`ix.Heal(ctx)` 先做一次内部巡检，健康时为空操作（`Healed=false`，不改任何状态）；
发现不一致时：

1. 定位**第一个对不上的高度**，从它前一个高度向下找到索引与数据源一致的共同祖先；
2. 回滚深度 = 链尖 − 共同祖先。深度 **> `MaxReorgDepth` 时返回 `KindReorgTooDeep`
   明确拒绝，索引保持原样**（先做深度判断再回滚，不产生任何改动）；
3. 深度允许时回滚到共同祖先，再从 `祖先+1` 到数据源链尖**按顺序重建**受影响区间。

修完后按高度与按交易查询的结论，与“把库清空从头全量重放”完全一致
（测试中用独立全量重放库逐块、逐交易比对）。重复执行修复是幂等的：
第二次巡检为健康即空操作，不会产生重复记录或计数漂移。
整个“对账-回滚-重建”在 `stateMu` 写锁与提交串行锁下原子进行，
与摄入、巡检互斥，外部观察不到中间状态。

## 重组留痕（`AuditTrail`）

被重组/自愈放弃的旧分支不再一删了之：回滚时按区块记录高度、区块哈希、
父哈希与全部交易标识，独立持久化到 `audit-trail.json`（与主检查点分离）。

- 每次重组产生一个 `AbandonedEvent`（含事件序号、分支标识、原因
  `reorg`/`heal`、时间戳与一组区块记录），常规摄入重组记为 `reorg`，
  巡检自愈回滚记为 `heal`。
- 重启后仍可反查：`LookupByHeight(h)` 按高度、`LookupByTx(txHash)` 按交易
  查它曾经属于哪个被放弃分支；`Events()` 按事件先后返回快照。
- **纯旁路审计**：留痕不影响 `BlockAt`/`TxByHash`/`Tip` 的结论，被放弃区块
  不会因留痕重新出现在常规查询里。
- 容量控制由 `AuditPolicy` 配置：
  - `MaxEvents`：保留事件条数上限，超出按先进先出裁剪（记录清空的事件删除）；
  - `PruneBelowHeight`：清理高度小于该值的区块记录；
  - `AutoPrune`：每次追加后自动套用策略；也可随时手动 `Prune(policy)`。
  - 零值策略表示永久保留。清理只动留痕文件，不触碰主索引正确性；
    留痕自带互斥锁并原子写盘，并发追加/清理/反查不会写坏。

## 与重组深度上限的兼容关系

巡检**不受** `MaxReorgDepth` 影响（只读，只报告影响范围）；
自愈与常规摄入重组**共用同一上限与同一把变更锁**：
深度 `链尖−共同祖先` 超限即拒绝并保持索引原状，留痕也只在回滚真正发生时写入。

## 配置项（`Config`）

| 字段 | 说明 | 默认 |
|---|---|---|
| `StoreDir` | 检查点持久化目录（`checkpoint.json`，原子写入） | 必填 |
| `MaxReorgDepth` | 允许的最大重组深度，超过即拒绝（自愈同样适用） | 0（任何重组都拒绝，建议显式设置） |
| `Workers` | 并发拉取协程数 | 1 |
| `PollBlocks` | 本次同步目标高度上限，0 表示跟到数据源链尖 | 0 |
| `MaxRetries` | 临时失败最大重试次数 | 5 |
| `Audit` | 重组留痕保留策略（`AuditPolicy`） | 零值：启用留痕、永久保留、不自动清理 |

## 并发与恢复

- 多个拉取协程并发取数，提交由单一把关者按高度顺序串行执行，
  查询（`BlockAt` / `TxByHash` / `Tip`）只读已提交状态，无竞态、无中间破损。
- `stateMu` 把“回滚+重建”这类多步变更包成原子区间：巡检在其读锁内取快照，
  与摄入相撞时只可能看到变更前或变更后的一致状态，不会把正常写入误判为脏数据。
- 每次写入/回滚后原子持久化检查点；留痕独立原子持久化。重启后 `NewIndexer`
  同时恢复索引进度与历史留痕，不重复、不丢失。
- 关键指标通过 `Indexer.Met`（原子计数）暴露：已应用区块/交易、重复、
  重组次数、回滚区块数、临时/不可恢复失败、非法区块。

## 验证方法

```bash
go build ./...
go test ./...              # 功能测试（含原有全部用例，不回归）
go test -race -v ./...     # 竞态检测 + 查看覆盖板块/高度/区块标识/判定依据日志
```

巡检/自愈/留痕相关测试覆盖：

- `TestInspectHealthyReadOnly`：健康索引巡检报告干净，检查点字节与记录计数不变；
- `TestInspectClassifiesIssues`：缺高与游离交易被分到各自类别；
- `TestHealForkEqualsFullReplay` / `TestHealGapEqualsFullReplay`：
  分叉/缺高后自愈，按高度与按交易结论与独立全量重放库逐块逐交易一致；
- `TestHealIdempotent`：修复连跑 3 次，第二次起为空操作，记录数无漂移；
- `TestHealRejectedWhenTooDeep`：自愈深度超上限被拒绝，索引原样；
- `TestAuditTrailRestartLookup`：留痕重启后仍可按高度/交易反查，常规查询不含被放弃数据；
- `TestAuditTrailRetention`：条数上限 / 按高度清理 / AutoPrune / 重启保留；
- `TestAuditTrailConcurrentSafe` / `TestPruneDoesNotAffectIndex`：
  留痕并发不写坏，清理不影响主索引；
- `TestInspectConcurrentWithIngestion` / `TestHealConcurrentWithInspect`：
  巡检与并发摄入、自愈与并发巡检同时进行，无竞态且只观察到一致状态。

原有测试（正常推进、重复摄入幂等、浅重组回滚重建、超限重组拒绝、并发摄入、
非法数据分类、临时失败重试、不可恢复失败后的重启恢复）保持通过。
